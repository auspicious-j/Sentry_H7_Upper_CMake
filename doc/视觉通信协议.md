# 视觉通信协议

本文档根据 `ApplicationCpp/App/Inc/Vision.h`、`ApplicationCpp/App/VisionApp.cpp`
和 `ApplicationCpp/Io/Vision` 的接收链路整理。

## 1. 通信方式

- 传输通道：USB Device CDC（虚拟串口）。
- 接收入口：`USB_DEVICE/App/usbd_cdc_if.c` 中的 `CDC_Receive_HS()`。
- 接收回调只搬运字节：`VisionLink_OnUsbReceive(Buf, *Len)`（`ApplicationCpp/Io/Vision`）。
- 解析在 `VisionTask` 中完成：`OS_VisionCallback()` 每周期先调用 `VisionLink_Poll()`
  消帧并发布 `vision_frame_mailbox()`，再调用 `Vision_DataTransmit()` 回传状态。
- 目标判定在 Gimbal 图的 `Vision_Target_Node` 中完成：读取原始帧快照，结合 IMU
  与发射状态，发布 `vision_target_mailbox()`。
- 结构体使用 `__attribute__((packed))`，字段按声明顺序连续排列，不插入对齐填充。
- 代码中没有实现校验和或 CRC；帧尾字段用于基本的帧边界标识。

## 2. 视觉模块发送给底盘（接收帧）

接收帧对应 `VisionReceive`（`ApplicationCpp/App/Inc/Vision.h`），帧头为 `0xA5`，
帧尾字段为结构体最后的 `end_frame`（需为 `0x5A`）。线上布局由
`ApplicationCpp/Io/Vision/VisionProtocol.hpp` 的 `vision_receive_wire` 镜像，
并用 `static_assert(sizeof(...) == 88)` 锁定。

| 顺序 | 字段 | 类型 | 含义 |
|---:|---|---|---|
| 1 | `header` | `uint8_t` | 帧头，必须为 `0xA5` |
| 2 | `mode` | `uint8_t` | 0 无目标，1 装甲板，2 符 |
| 3~ | `armor`（联合体，仅装甲板模式） | 结构体 | `base_yaw`、`yaw`、`pitch`、`incident_yaw`、`distance`、`hit_radius`，均为 `float` |
| 3~ | `rune`（联合体，仅打符模式） | 结构体 | `base_yaw`、`hit_radius`、`yaw[2]`、`pitch[2]`、`incident_yaw[2]`、`distance[2]`、`hit_time[2]`（`float`）、`id[2]`（`int8_t`） |
| 4 | `force_shoot` | `uint8_t` | 强制开火：0 不开火，1 开火 |
| 5 | `linear_x` | `float` | AI 底盘线速度（视觉坐标系） |
| 6 | `linear_y` | `float` | AI 底盘线速度（视觉坐标系） |
| 7 | `angular_z` | `float` | AI 旋转角速度 |
| 8 | `align_yaw` | `float` | 与起伏路段对齐角度 |
| 9 | `look_yaw` | `float` | 符/前哨站注视角 |
| 10 | `look_pitch` | `float` | 符/前哨站注视角 |
| 11 | `spin_mode` | `uint8_t` | 小陀螺：0 关闭，1 开启 |
| 12 | `sentry_mode` | `uint8_t` | 哨兵模式：1 进攻，2 防守，3 移动 |
| 13 | `armor_mode` | `uint8_t` | 目标模式：0 装甲板，1 前哨，2 符 |
| 14 | `align_mode` | `uint8_t` | 对齐模式：0 不对齐，1 对齐 |
| 15 | `energy_activation` | `uint8_t` | 能量机关：0 不激活，1 小符，2 大符 |
| 16 | `buy_life` | `uint8_t` | 是否购买复活 |
| 17 | `remote_buy_blood` | `uint8_t` | 远程购买血量次数 |
| 18 | `remote_buy_bullet` | `uint8_t` | 远程购买弹药次数 |
| 19 | `buy_projectile` | `uint16_t` | 购买弹药数量 |
| 20 | `end_frame` | `uint8_t` | 帧尾，需为 `0x5A` |

底盘收到数据后，`VisionLink` 的消帧器会在 USB 字节流中向后扫描 `0xA5`，凑满
`vision_receive_wire` 后校验帧尾并解码为 `vision_frame_snapshot`，再发布到快照邮箱：

```c
vision_frame_mailbox().publish(decoded_frame, now_us);
```

随后云台图节点 `Vision_Target_Node` 读取该快照，更新云台目标、发射请求；
底盘速度与哨兵指令由各自的输入节点直接读取同一份快照。

## 3. 底盘发送给视觉模块（发送帧）

发送帧对应 `VisionTransmit`，帧头为 `0x5A`，帧尾为 `0xA5`。字段顺序如下：

| 顺序 | 字段 | 类型 | 含义 |
|---:|---|---|---|
| 1 | `header` | `uint8_t` | 帧头，固定 `0x5A` |
| 2 | `detect_color` | `uint8_t` | 目标颜色：0 红，1 蓝 |
| 3 | `mode` | `uint8_t` | 模式：0 装甲板，1 前哨，2 符 |
| 4 | `roll` | `float` | 横滚角，来自 `INS.roll` |
| 5 | `pitch` | `float` | 俯仰角，来自 `INS.pitch` |
| 6 | `top_yaw` | `float` | 上云台角度 |
| 7 | `diff_yaw` | `float` | 大小 yaw 电机之间的角度差 |
| 8 | `diff_pitch` | `float` | pitch 电机位置角度 |
| 9 | `bullet_speed` | `float` | 当前弹速 |
| 10 | `robo_status` | `uint8_t` | 机器人状态；当前代码固定填 `0xFF` |
| 11 | `AI_Judge_data` | `Judge_Data_e` | 比赛状态、血量、弹量、哨兵状态等裁判系统数据 |
| 12 | `see_enemy` | `uint8_t` | 目标状态，取 `Vision_Target_Node` 发布的 `is_valid` |
| 13 | `end_frame` | `uint8_t` | 帧尾，固定 `0xA5` |

发送数据由以下代码完成：

```c
CDC_Transmit_HS((uint8_t*)&vision_transmit, sizeof(vision_transmit));
```

## 4. 接收回调与缓冲区关系

USB CDC 接收到数据后，协议栈把数据放入 `UserRxBufferHS`，再调用：

```c
CDC_Receive_HS(uint8_t *Buf, uint32_t *Len)
```

回调内部只把 `Buf` 和实际长度 `*Len` 交给 `VisionLink_OnUsbReceive()` 搬进环形缓冲，
不做解析；处理完成后重新调用 `USBD_CDC_ReceivePacket()`，使 USB CDC 继续接收下一包。

解析由 `VisionTask` 调用 `VisionLink_Poll()` 完成：跨 USB 包组帧、校验帧头/帧尾、
解码为 `vision_frame_snapshot` 并发布快照邮箱。

## 5. 当前协议实现的注意事项

1. 接收端按 `sizeof(vision_receive_wire)` 限制每次写入量，不会因半帧或超长包越界。
2. 接收端会校验 `end_frame == 0x5A`；但没有校验和/CRC，帧内容损坏仍可能被当作有效数据。
3. `float`、整数的字节序依赖双方 CPU 的实现；当前协议默认双方使用相同的字节序和浮点格式。
4. 消帧器会跨多次 USB 回调保留未完成的帧，因此一个完整视觉帧可以跨越多个 USB 包。

## 6. 给上位机脚本使用的精确帧定义

### 6.1 通用规则

- 所有字段按表格顺序连续排列，偏移量从 0 开始。
- `uint8_t` 占 1 字节，`uint16_t` 占 2 字节，`uint32_t` 占 4 字节，`float` 占 4 字节。
- STM32 与常见 PC 均使用 IEEE-754 单精度浮点数；当前工程默认使用小端字节序（little-endian）。Python 可使用 `struct.unpack('<...')`。
- 结构体是 packed 布局，不能按 C 编译器默认对齐方式插入填充字节。
- 接收帧 `VisionReceive` 固定长度为 **88 字节**。
- 发送帧 `VisionTransmit` 固定长度为 **49 字节**。

### 6.2 上位机 → STM32：VisionReceive，88 字节

| 偏移 | 长度 | 格式 | 字段 |
|---:|---:|---|---|
| 0 | 1 | `B` | `header`，固定 `0xA5` |
| 1 | 1 | `B` | `mode`，0 无 / 1 装甲板 / 2 符 |
| 2 | 24 | — | `armor` 联合体：`base_yaw`(2)、`yaw`(6)、`pitch`(10)、`incident_yaw`(14)、`distance`(18)、`hit_radius`(22) |
| 2 | 50 | — | `rune` 联合体：`base_yaw`(2)、`hit_radius`(6)、`yaw[2]`(10)、`pitch[2]`(18)、`incident_yaw[2]`(26)、`distance[2]`(34)、`hit_time[2]`(42)、`id[2]`(50) |
| 52 | 1 | `B` | `force_shoot` |
| 53 | 4 | `f` | `linear_x` |
| 57 | 4 | `f` | `linear_y` |
| 61 | 4 | `f` | `angular_z` |
| 65 | 4 | `f` | `align_yaw` |
| 69 | 4 | `f` | `look_yaw` |
| 73 | 4 | `f` | `look_pitch` |
| 77 | 1 | `B` | `spin_mode` |
| 78 | 1 | `B` | `sentry_mode` |
| 79 | 1 | `B` | `armor_mode` |
| 80 | 1 | `B` | `align_mode` |
| 81 | 1 | `B` | `energy_activation` |
| 82 | 1 | `B` | `buy_life` |
| 83 | 1 | `B` | `remote_buy_blood` |
| 84 | 1 | `B` | `remote_buy_bullet` |
| 85 | 2 | `H` | `buy_projectile` |
| 87 | 1 | `B` | `end_frame`，固定 `0x5A` |

Python 解析格式（联合体用 50 字节占位，按 `mode` 再解内部字段）：

```python
RX_FORMAT = '<BB50sB6f8BHB'
assert struct.calcsize(RX_FORMAT) == 88
```

发送帧的 `end_frame` 需填入上位机约定的帧尾。当前接收代码会校验帧尾 `0x5A`。

### 6.3 STM32 → 上位机：VisionTransmit，49 字节

| 偏移 | 长度 | 格式 | 字段 |
|---:|---:|---|---|
| 0 | 1 | `B` | `header`，固定 `0x5A` |
| 1 | 1 | `B` | `detect_color`，0 红色，1 蓝色 |
| 2 | 1 | `B` | `mode`，0 装甲板，1 前哨，2 符 |
| 3 | 4 | `f` | `roll` |
| 7 | 4 | `f` | `pitch` |
| 11 | 4 | `f` | `top_yaw` |
| 15 | 4 | `f` | `diff_yaw` |
| 19 | 4 | `f` | `diff_pitch` |
| 23 | 4 | `f` | `bullet_speed` |
| 27 | 1 | `B` | `robo_status`，当前固定 `0xFF` |
| 28 | 1 | `B` | `AI_Judge_data.game_progress` |
| 29 | 2 | `H` | `AI_Judge_data.remain_time`，秒 |
| 31 | 2 | `H` | `AI_Judge_data.current_hp` |
| 33 | 2 | `H` | `AI_Judge_data.projectile` |
| 35 | 4 | `I` | `AI_Judge_data.sentry_info` |
| 39 | 2 | `H` | `AI_Judge_data.sentry_info_2` |
| 41 | 1 | `B` | `AI_Judge_data.sentry_info_3` |
| 42 | 1 | `B` | `AI_Judge_data.rune_state` |
| 43 | 2 | `H` | `AI_Judge_data.ally_outpost_hp` |
| 45 | 2 | `H` | `AI_Judge_data.ally_base_hp` |
| 47 | 1 | `B` | `see_enemy` |
| 48 | 1 | `B` | `end_frame`，固定 `0xA5` |

Python 解析格式：

```python
TX_FORMAT = '<3B6fB B3H I H 2B 2H 2B'.replace(' ', '')
# 等价于：<3B6fBB3HIH2B2H2B
assert struct.calcsize(TX_FORMAT) == 49
```

### 6.4 Python 打包示例

```python
import struct

RX_FORMAT = '<BB50sB6f8BHB'      # 88 字节整帧，见 6.2
assert struct.calcsize(RX_FORMAT) == 88
RX_HEADER, RX_END = 0xA5, 0x5A

# 联合体内部布局（mode 决定用哪一套，另一套的字节在 50 字节槽内被忽略）
ARMOR_FORMAT = '<6f'    # base_yaw, yaw, pitch, incident_yaw, distance, hit_radius
RUNE_FORMAT = '<12f'    # base_yaw, hit_radius, yaw[2], pitch[2],
                        # incident_yaw[2], distance[2], hit_time[2]
RUNE_IDS = '<2b'        # id[2]
assert struct.calcsize(ARMOR_FORMAT) == 24
assert struct.calcsize(RUNE_FORMAT) + struct.calcsize(RUNE_IDS) == 50


def build_frame(mode, union_body, *, force_shoot=0, linear_x=0.0, linear_y=0.0,
                angular_z=0.0, align_yaw=0.0, look_yaw=0.0, look_pitch=0.0,
                spin_mode=0, sentry_mode=3, armor_mode=0, align_mode=0,
                energy_activation=0, buy_life=0, remote_buy_blood=0,
                remote_buy_bullet=0, buy_projectile=0):
    if len(union_body) > 50:
        raise ValueError('联合体内容超过 50 字节')
    return struct.pack(
        RX_FORMAT, RX_HEADER, mode, union_body.ljust(50, b'\x00'),
        force_shoot, linear_x, linear_y, angular_z,
        align_yaw, look_yaw, look_pitch,
        spin_mode, sentry_mode, armor_mode, align_mode,
        energy_activation, buy_life, remote_buy_blood,
        remote_buy_bullet, buy_projectile, RX_END)


def split_union(mode, body):
    """解 50 字节联合体，供上位机自测。"""
    if mode == 1:
        return dict(zip(('base_yaw', 'yaw', 'pitch', 'incident_yaw',
                         'distance', 'hit_radius'),
                        struct.unpack(ARMOR_FORMAT, body[:24])))
    if mode == 2:
        v = struct.unpack(RUNE_FORMAT, body[:48])
        return dict(base_yaw=v[0], hit_radius=v[1],
                    yaw=v[2:4], pitch=v[4:6], incident_yaw=v[6:8],
                    distance=v[8:10], hit_time=v[10:12],
                    id=struct.unpack(RUNE_IDS, body[48:50]))
    return {}


# 打装甲板：base_yaw=10, yaw=12, pitch=5, incident_yaw=0.3, distance=2000, hit_radius=150
armor = build_frame(1,
                    struct.pack(ARMOR_FORMAT, 10.0, 12.0, 5.0, 0.3, 2000.0, 150.0),
                    linear_x=1.2, sentry_mode=1)

# 打符：两个符的 yaw/pitch/incident_yaw/distance/hit_time，最后 2 字节为 id
rune = build_frame(2,
                   struct.pack(RUNE_FORMAT, 0.0, 150.0,
                               10.0, 170.0, 5.0, 6.0, 0.2, 0.3,
                               2000.0, 2100.0, 0.0, 0.0)
                   + struct.pack(RUNE_IDS, 0, 1),
                   armor_mode=2, energy_activation=1)

assert len(armor) == len(rune) == 88
assert split_union(1, armor[2:52])['distance'] == 2000.0
```

发送时应保证一次写入完整 **88 字节**帧（不要拆成多次 `write`），并在发送频率上留出 USB CDC 处理时间。STM32 侧的消帧器能跨 USB 包重组帧，但拆包会放大丢包窗口。接收 STM32 的 49 字节帧时，先检查 `data[0] == 0x5A` 与 `data[48] == 0xA5`，再按 6.3 的表使用 little-endian 解包。
