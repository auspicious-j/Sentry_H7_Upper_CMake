日期：2026-10-09。

## 当前结构与数据流

应用组合根依次注册节点、展开内部图、验证并编译执行计划，再统一 configure/start。运行期仍由一个插件任务顺序执行图；两个累计器是独立对象，未新增并行任务。

~~~mermaid
flowchart LR
    W["Watch 请求"] --> A["RobotApplication 帧边界采样"]
    A --> C["ComparisonDemoNode / ID 100"]
    C -.组装.-> I["合成输入 / ID 101"]
    I --> R["参考累计器 / ID 102"]
    I --> N["候选累计器 / ID 103"]
    R --> X["只读比较 / ID 104"]
    N --> X
    X --> D["g_robot_debug.comparison"]
~~~

四条节点依赖是 101→102、101→103、102→104、103→104；容器组装关系不额外计为依赖边。参考/候选是同一算术类型的两个实例，目的是验证状态隔离和比较框架，尚不是两套不同的业务算法。

每帧输入为一个整数，默认 7；输入身份使用帧序号和帧起点的单调时间。每路独立执行 `sum = (sum + input) % 1000000`，输出两个 double 通道：`[0]` 为累计值，`[1]` 为实际计算步数。两个通道容差均为 0。候选偏差只加在导出的第 0 通道，不改变其内部累计值。

候选暂停时保留旧样本；比较器读取它的原始身份，因此返回 Unaligned。恢复后只处理新一帧，不补算暂停期间输入。单独重置候选会分配新的状态版本，参考对象不变。共同重置分别清空两对象、采用相同版本；若候选仍暂停，则不能当帧恢复对齐。共同重置与候选重置同帧出现时共同重置优先。所有统计值和历史最大差保留至系统重新启动，uint32 计数允许自然回绕。

## Watch 上板观察步骤

入口为 `g_robot_debug.comparison`。以下是**预期结果，尚无本版本上板实测记录**。每次修改后至少运行一帧再读结果。建议在 RobotApplication::processFrame 中 updateComparisonDebug() 返回后的下一行设置断点，读取完整结果，并在此修改下一帧请求后继续执行。任意时刻暂停可能恰好停在字段更新或请求采样中间；Watch 不提供跨字段原子事务。

先确认 `g_robot_debug.initialized=1`、`init_error=0`，默认规模为 `graph_node_count=25`、`graph_edge_count=14`、`plan.plan_count=2`。

| 操作（字段均位于 comparison 下） | 预期观察 |
| --- | --- |
| 初始 input_value=7、candidate_bias=0、pause_candidate=0 | status=4（Equal），difference_valid=1，difference[0/1]=0，两路身份和步数相同 |
| candidate_bias=3 | status=5（Different），difference[0]=3、difference[1]=0，different_count 增长 |
| candidate_bias 恢复 0 | 无失步时恢复 Equal；historical_max_abs_difference 仍至少为 3 |
| pause_candidate=1，运行若干帧 | 已有候选结果时 status=1（Unaligned），候选 step/sequence 保持，参考继续；difference_valid=0 |
| pause_candidate 恢复 0 | 输入 sequence/time 再相同，但 step 仍不同，继续 Unaligned |
| pause_candidate=0、candidate_bias=0，并把 reset_all_request 改成不同数值 | 两路相同 state_epoch，从 step=1 继续，恢复 Equal |
| 把 reset_candidate_request 改成不同数值 | 候选重置，参考继续；epoch 不同，Unaligned；再共同重置恢复 |
| pause_candidate=1 后请求共同重置 | 候选 present=0，status=0（Missing）；恢复运行仍有失步，应再共同重置 |
| input_value 或 candidate_bias 写入 1001 | 对应 applied_* 保留上次合法值，rejected_frames 每个非法请求帧加 1；其他合法请求仍处理 |
| 切换 g_robot_debug.plan.requested_plan 为 0/1 | 原有计划演示交换顺序；本比较链仍执行，正常对齐状态不受影响 |

可写字段只有 `input_value`、`candidate_bias`、`pause_candidate`、`reset_all_request`、`reset_candidate_request`。两个整数参数合法范围均为 [-1000,1000]；`applied_input_value`、`applied_candidate_bias` 表示最近接受的参数。暂停期间偏差即使已接受，也要等候选再次执行才反映到结果。

重置请求是变化触发的事件编号，例如 0→1→2；持续保持 1 不会每帧重置，1→0 也会触发一次。两次修改若都发生在同一帧采样前，只能看到最终值。

`difference_valid=0` 时差值字段的 0 不代表相等；必须先看 status。当前差值最大值为 `max_abs_difference`，历史值为 `historical_max_abs_difference`。Equal/Different/Unaligned 分别累计，Missing/InvalidTolerance/NonFinite 归入 `invalid_count`；若比较节点本身被调度跳过，只清空当前结果，不增加已执行比较的计数。

## 稳定快照读取

读取顺序为：

```cpp
robot::framework::TimedSnapshot<unsigned> sample;
mailbox.copyTo(sample);
const auto freshness = robot::framework::evaluateSnapshot(sample, clock.nowUs(), 5000U);
```

`sample`、`sample.sequence` 和 `freshness` 属于同一份发布数据。复制完成后取时钟，避免用帧起点判断帧中到达的样本。`sampled_at_us=0` 合法；`present=false` 才表示空状态。未来时间返回 ClockMismatch，年龄等于 TTL 仍为 Fresh。

此接口不能自动解决不同时间域、DMA 缓冲所有权或时钟实现的线程安全。锁必须保护完整值和元数据；不能把两次独立读取拼成一份快照。

## 结果对比契约

比较前双方必须拥有一致的输入与状态时间线：

| 字段 | 含义 |
| --- | --- |
| `sampled_at_us` | 原始输入时间；不能用读取或输出时间替代 |
| `input_sequence` | 原始输入序号 |
| `state_epoch` | 双方一致定义的初始状态/重置版本 |
| `step` | 该版本下的计算步数 |

这些字段一致只是比较的必要条件。调用者还必须保证输入完整、配置一致、单位/坐标系/通道顺序一致；比较器不能证明两份被错误标号的数据实际相同，也不会自动创建独立业务状态。

以下只是通用算术样本：

```cpp
using namespace robot::framework;
const ComparisonKey key{100U, 7U, 1U, 3U};
const ComparisonSample<2U> reference{key, {10.0, -2.0}, true};
const ComparisonSample<2U> candidate{key, {10.2, -2.0}, true};
const ComparisonTolerance<2U> tolerance{{0.5, 0.0}};
const auto result = compareOutputs(reference, candidate, tolerance);
// Equal：两项均在容差内；difference = candidate - reference。
```

状态按以下顺序判定：

| 状态 | 含义 |
| --- | --- |
| `Missing` | 任一方未发布完整结果 |
| `Unaligned` | 输入身份、状态版本或步数不同，不进行数值比较 |
| `InvalidTolerance` | 容差为负、NaN 或无穷 |
| `NonFinite` | 数值包含 NaN/Inf，或差值超出有限范围 |
| `Equal` | 全部通道的绝对差小于等于容差 |
| `Different` | 至少一个通道超出容差 |

只有 Equal/Different 时差值字段有效。异常不会留下半份通道结果。接口不调用任一套算法、不修改传入样本、不推进控制状态、不发送硬件命令。它使用 double 数值，不能用于要求保留超过 double 整数精度范围的整数逐位比较。

## 浮点编译约束

ARMClang 默认可能启用 `__FINITE_MATH_ONLY__=1`，编译器会假设 NaN/Inf 不存在。比较接口需要识别这些异常，因此包含 `OutputComparison.hpp` 的新翻译单元必须使用 `-fno-fast-math`；否则头文件明确报错。

现在仅 ComparisonDemoNode.cpp 包含数值比较算法头文件，CMake 和 Keil 均为它单独设置 -fno-fast-math。ComparisonTypes.hpp 可供应用接线和其他头文件持有数据，旧业务以及全局浮点选项未改动。后续新增比较翻译单元也要单独设置该选项；删除检查会使 NonFinite 契约失效。

## 性能观察边界

`last_node_duration_us` 和 `max_node_duration_us` 现在由实际执行节点更新。它们仍是全图共用字段：最近值代表最后执行节点，最大值代表所有测得节点调用中的最大耗时。

条件跳过、状态跳过和依赖阻塞不调用节点探针。`onEnter/onExit/onPlanChanged` 及调度开销不属于单次 `process()` 耗时；应用帧级耗时依旧包含调度和 Debug 汇总。尚未增加逐节点统计表、任务周期抖动、P95/P99 或完整 trace。
